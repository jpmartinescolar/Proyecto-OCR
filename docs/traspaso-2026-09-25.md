## 5. Fase 1 de Google (propuesta, NO implementada, pendiente de revisión)
Objetivo: archivo recibido → identificar tipo → validar → contar documentos → separar → registrar en SQL → guardar derivados → relacionar con el original. Sin OCR completo todavía.

- **Modelo**: `bandejas` 1–N `archivos` (origen SUBIDO o EXTRAIDO_ZIP con `padre_id`; `nombre_original`, `mime_detectado`, `sha256`, `num_paginas`, estado) 1–N `procesamientos` (versión de la lógica, motor, detalle por página en JSON) 1–N `documentos` (ULID, número D01…, páginas inicio/fin, tipo, confianza, estado, motivos de revisión, REFERENCIA o DERIVADO, `sustituido_por`). Fase 2: `documentos` 1–N `extracciones`.
- **Estados de archivo**: RECIBIDO, EN_COLA/PROCESANDO, PROCESADO, PROCESADO_CON_INCIDENCIAS, NO_SOPORTADO, ERROR.
- **Estados de documento**: LISTO, REQUIERE_REVISION (motivos: NO_PARECE_FACTURA, SEPARACION_INCIERTA, VARIOS_TIPOS_MEZCLADOS, ILEGIBLE, BAJA_CONFIANZA, DUPLICADO, PAGINA_EN_BLANCO), DESCARTADO, ERROR, SUSTITUIDO.
- **Storage recomendado**: dos buckets por entorno, `…-raw` (originales, inmutables, retención larga) y `…-docs` (derivados, regenerables). Rutas sin nombre del cliente: `raw/{org}/{bandeja}/{archivoId}.{ext}` y `docs/{org}/{bandeja}/{archivoId}/{procesamientoId}/{documentoId}.pdf`. El nombre original va en SQL y en los metadatos, y se sirve al descargar con `Content-Disposition`.
- **Sin duplicar**: imagen o PDF de un documento = referencia al original; solo los PDF con varios documentos y el contenido de ZIP generan derivados.
- **Reproceso**: nuevo `procesamiento` y nueva carpeta; los documentos anteriores pasan a SUSTITUIDO; nunca se sustituye automáticamente un documento validado o contabilizado.
- **Servicios**: Cloud Tasks (encola desde `/confirm`) → nuevo Cloud Run privado `bandeja-contable-procesador`; misma BD; Secret Manager; Logging.
- **Separación**: parte determinista (`file-type`, `pdf-lib`, `pdfjs`, `yauzl`, `sharp`) + clasificador por página intercambiable (modelo de lenguaje con visión vía Vertex AI UE y/o Document AI). Una factura de varias páginas no debe partirse.
- **Implementación**: carpeta nueva en este repo (como `gcp-bandeja-contable-api/`), desplegada con `gcloud run deploy --source`, probada con archivos de muestra.

**Decisiones abiertas**: (1) dos buckets y recrear el de dev; (2) ULID con prefijo; (3) quitar CIF y nombre de las rutas; (4) estados y motivos; (5) clasificador inicial; (6) límites de ZIP y un solo nivel; (7) Excel "pendiente de flujo propio"; (8) 20–30 archivos reales anonimizados de muestra; (9) aviso de Google a Salesforce al terminar.
